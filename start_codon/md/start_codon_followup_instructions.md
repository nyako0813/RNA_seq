## Step 1（優先・必須）: 今回のフル実行で見つかった2件のバグ修正をコミット・プッシュ

フル実行中に発見・修正したが、まだコミットされていない可能性がある変更を確認し、通常のgit運用（`origin/main`が正、pushは即時）に従ってコミットすること。

1. `old_locus_tag`がCDS行ではなくgene行にしか存在しないため空欄になっていた不具合の修正（locus_tag→old_locus_tagのルックアップをgene行から構築するよう変更した箇所）
2. IS転移酵素19遺伝子座（ORF-A/ORF-Bにフレームシフトで分割されたCDSが同一locus_tagを共有するケース）でクラッシュしていた不具合の修正（これら19件をバッチ対象から除外する形で対応した箇所）

- `git status` / `git diff` で未コミットの変更を確認し、コミットメッセージには「何を・なぜ直したか」を簡潔に記載する。
- テストが通ることを確認してからコミットする。
- push前に `git fetch && git status` でリモートと同期していることを確認する。

## Step 2（優先度高）: 「要確認」34件、特にRNA-seqステップ比が極端に大きいケースの深掘り

以下の遺伝子は、RNA-seqステップ比が100〜500超という異常に強い値を示しているにもかかわらず、BLASTが支持する候補と一致していない。RNA-seq側のシグナルが強すぎる場合、真の代替開始点ではなく「隣接遺伝子・オペロン内リード貫通・別の転写物からのシグナル漏れ」を拾っている可能性がある。以下を確認すること。

対象遺伝子（ステップ比の絶対値が大きい順、抜粋）:
- MA_RS26685（old: なし）— ステップ比 521.46
- MA_RS15470（old: MA_2951）— ステップ比 222.83
- MA_RS20445（old: MA_3916）— ステップ比 106.09
- MA_RS23000（old: MA_4400）— ステップ比 45.07
- MA_RS07375（old: MA_1421）— ステップ比 45.23
- （残り29件は添付の`要確認_34件_詳細`シート参照）

各遺伝子について:

1. GFFで**両隣の遺伝子**（前後それぞれ1〜2遺伝子）のstrand・座標を確認し、`rna_best_pos`が対象遺伝子ではなく隣接遺伝子の実際の開始点やプロモーター/RBS領域と一致していないか調べる。
2. 対象領域のBAMカバレッジを`samtools depth`（または`samtools tview`/IGV等）で目視確認し、ステップの立ち上がり位置が本当に`rna_best_pos`にあるか、それとも読み取りの重なり・アンチセンス転写・オペロンのポリシストロニックな転写開始点によるものかを判断する。
3. 上記の結果に基づき、各遺伝子を次のいずれかに再分類する。
   - 「真の代替開始点候補」（BLASTとは食い違うが、RNA-seq根拠は独立して妥当）
   - 「隣接遺伝子/転写物由来のアーティファクト」（除外・注記対象）
   - 「判断保留」（追加データが必要）
4. 判定理由を1行程度で`要確認_34件_詳細`相当の一覧に追記した更新版CSV/Excelとして出力する。

## Step 3（任意・時間があれば）: 非正準コドンで支持されている95件の簡易チェック

現行アノテーションの開始コドンが元々非正準（ATG/GTG/TTG以外）なのに「支持」判定になっている95件について、上位10〜20件（BLAST同一性が高い順）だけで良いので、BLASTの`blast_qstart_aa`が1であること（＝オルソログの開始点と一致していること）を再確認し、非正準コドンのまま採用して問題なさそうかコメントを添える。時間が無ければStep 2を優先し、これは後回しでよい。
